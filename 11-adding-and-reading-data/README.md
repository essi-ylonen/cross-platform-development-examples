# SQLite Students, Part 2: Adding and Reading Data

A React Native and Expo example that demonstrates how to add student data to a local SQLite database and read the saved rows back into the application.

This project continues the concepts introduced in `sqlite-students-part1`. It is a separate example project so that you can study the database creation and the data operations in clear stages.

## Learning objectives

After studying this example, you should understand how to:

- insert a new row into an SQLite table
- use placeholders in a parameterized SQL statement
- read rows with `SELECT` and `getAllAsync()`
- connect asynchronous database operations to React state
- display database rows in a React Native list
- refresh the list after inserting data
- verify that SQLite data persists after the application restarts

## Technologies used

- React Native
- Expo
- JavaScript
- SQLite
- `expo-sqlite`
- `react-native-safe-area-context`

## What the application does

The application allows the user to:

1. enter a student's name
2. enter an email address
3. enter a degree programme
4. save the student in a local SQLite database
5. read all saved students
6. display the students in a list

The data is stored locally on the device or emulator. This example does not use a Node.js server, an Express route, an HTTP request, or `fetch()`.

## The `students` table

The application uses a table with the following structure:

```sql
CREATE TABLE IF NOT EXISTS students (
  id INTEGER PRIMARY KEY NOT NULL,
  name TEXT NOT NULL,
  email TEXT NOT NULL,
  programme TEXT NOT NULL
);
```

| Column | Type | Purpose |
|---|---|---|
| `id` | `INTEGER` | Unique identifier generated by SQLite |
| `name` | `TEXT` | Student's name |
| `email` | `TEXT` | Student's email address |
| `programme` | `TEXT` | Student's degree programme |

`PRIMARY KEY` identifies every row uniquely. Because `id` is an `INTEGER PRIMARY KEY`, SQLite generates an ID when a row is inserted.

`NOT NULL` means that the column must receive a value. The application also validates the input before running the SQL statement.

## Adding a student

A new student is inserted with `runAsync()`:

```javascript
export async function addStudent(name, email, programme) {
  const db = await dbPromise;

  return db.runAsync(
    'INSERT INTO students (name, email, programme) VALUES (?, ?, ?)',
    name.trim(),
    email.trim(),
    programme.trim()
  );
}
```

The SQL statement is:

```sql
INSERT INTO students (name, email, programme)
VALUES (?, ?, ?)
```

The question marks are **placeholders**. The actual values are passed separately to `runAsync()`.

This is better than joining user input directly into the SQL text. It also handles input containing characters such as apostrophes correctly.

### The generated row ID

`runAsync()` returns a result object. Its `lastInsertRowId` property contains the ID generated for the new row.

```javascript
export async function addStudent(name, email, programme) {
  const db = await dbPromise;

  const result = await db.runAsync(
    'INSERT INTO students (name, email, programme) VALUES (?, ?, ?)',
    name.trim(),
    email.trim(),
    programme.trim()
  );

  console.log('New student id:', result.lastInsertRowId);
  return result;
}
```

The application does not need to create the ID itself. SQLite creates it when the row is inserted.

## Validating the form

Before inserting a student, the application checks the form values:

```javascript
if (!name.trim() || !email.trim() || !programme.trim()) {
  Alert.alert(
    'Missing information',
    'Enter name, email and degree programme.'
  );
  return;
}
```

`trim()` removes whitespace from the beginning and end of a string. If a required value is missing or contains only spaces, `return` stops the save function.

An empty string is not the same as SQL `NULL`. Therefore, validation in the application is still useful even when the database columns use `NOT NULL`.

## Reading all students

The application reads rows with `getAllAsync()`:

```javascript
export async function getStudents() {
  const db = await dbPromise;

  return db.getAllAsync(
    'SELECT id, name, email, programme FROM students ORDER BY id DESC'
  );
}
```

The query contains three important parts:

- `SELECT id, name, email, programme` chooses the columns to return
- `FROM students` chooses the table
- `ORDER BY id DESC` sorts the rows from the largest ID to the smallest ID

Because new rows normally receive larger IDs, `ORDER BY id DESC` places the newest student first.

`getAllAsync()` returns an array of row objects. For example:

```javascript
[
  {
    id: 2,
    name: 'Alex Student',
    email: 'alex.student@example.com',
    programme: 'Computer Applications'
  },
  {
    id: 1,
    name: 'Emma Example',
    email: 'emma.example@example.com',
    programme: 'Business Information Technology'
  }
]
```

The values above are only example data.

If no students have been saved, the returned value is an empty array:

```text
Students from SQLite: []
```

This does not indicate an error. It means that the query succeeded but the table did not contain any rows.

## Connecting SQLite data to React state

The students shown by the application are stored in React state:

```javascript
const [students, setStudents] = useState([]);
```

The `loadStudents()` function reads the database rows and updates the state:

```javascript
async function loadStudents() {
  try {
    const rows = await getStudents();
    console.log('Students from SQLite:', rows);
    setStudents(rows);
  } catch (error) {
    Alert.alert('Reading failed', error.message);
  }
}
```

The sequence is:

```text
Run SELECT query
      ↓
Receive an array from getAllAsync()
      ↓
Call setStudents(rows)
      ↓
React updates the screen
```

The SQLite table and React state have different roles:

| SQLite table | React state |
|---|---|
| Persistent storage | Current in-memory data used by the component |
| Keeps rows when the app closes | Used to render the current screen |
| Updated with SQL operations | Updated with a state setter such as `setStudents()` |

In short:

```text
Table = stored data
State = data currently used and displayed by the app
```

## Saving and refreshing the list

A save function follows this sequence:

```javascript
async function handleAddStudent() {
  if (!name.trim() || !email.trim() || !programme.trim()) {
    Alert.alert(
      'Missing information',
      'Enter name, email and degree programme.'
    );
    return;
  }

  try {
    await addStudent(name, email, programme);
    setName('');
    setEmail('');
    setProgramme('');
    await loadStudents();
  } catch (error) {
    Alert.alert('Adding failed', error.message);
  }
}
```

The order is important:

1. **Validate:** Check that all required fields contain values.
2. **Await INSERT:** Wait until SQLite has saved the new row.
3. **Clear inputs:** Reset the form fields after a successful insert.
4. **Await SELECT:** Read all students again with `loadStudents()`.
5. **Update state:** Store the returned rows with `setStudents(rows)`.
6. **Re-render:** React updates the screen and shows the new student.

The application waits for `addStudent()` before calling `loadStudents()`. Without `await`, the read operation could begin before the insert has finished.

## Displaying the rows

The student array can be displayed with `FlatList`:

```javascript
<FlatList
  data={students}
  keyExtractor={(item) => item.id.toString()}
  renderItem={({ item }) => (
    <View style={styles.row}>
      <Text style={styles.name}>{item.name}</Text>
      <Text>{item.email}</Text>
      <Text>{item.programme}</Text>
    </View>
  )}
  ListEmptyComponent={<Text>No students saved yet.</Text>}
/>
```

The database `id` is converted to a string and used as the unique key for each list item.


## Local SQLite compared with the earlier REST example

| REST API example | Local SQLite example |
|---|---|
| React Native calls `fetch()` | React Native calls a database helper function |
| Data request uses a URL | No URL is needed |
| Request uses an HTTP method | Database operation uses SQL |
| Express handles a route | SQLite handles the query locally |
| `response.json()` produces data | `getAllAsync()` returns the rows |
| Data is stored behind the server | Data is stored on the device or emulator |

Both versions usually place the result in React state so that the user interface can render it.

## Summary

This example demonstrates the complete create-and-read cycle:

```text
Create: form → validation → INSERT → saved SQLite row
Read: SELECT → returned array → React state → rendered list
```

The key idea is that SQLite provides persistent local storage, while React state contains the data currently used to render the interface.
